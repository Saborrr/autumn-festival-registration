# Политика безопасности

## Поддерживаемая версия

Исправления безопасности применяются к ветке `main`.

## Как сообщить об уязвимости

Не публикуйте сведения об уязвимости, реальные персональные данные, секретные ключи или учётные данные в GitHub Issues.

Используйте **GitHub Private Vulnerability Reporting** в разделе **Security → Advisories → Report a vulnerability**. Если эта функция недоступна, свяжитесь с владельцем репозитория приватным каналом.

В сообщении укажите:

- затронутый URL или компонент;
- шаги воспроизведения;
- ожидаемое и фактическое поведение;
- возможное влияние;
- безопасное доказательство без выгрузки персональных данных.

## Чувствительные данные

Репозиторий не должен содержать:

- production-файл `.env`;
- SQLite-базу регистраций и её резервные копии;
- экспортированные `.xlsx` и `.docx` с данными участников;
- пароли администраторов и модераторов;
- секретные ключи Django, API-токены и SSH-ключи.

Если секрет случайно попал в Git, его необходимо немедленно отозвать и заменить. Удаление файла последующим коммитом не делает опубликованный секрет безопасным.
